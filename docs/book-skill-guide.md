# Book Skill：搜书、选择格式与下载

适用版本：`book-skill v0.2.5`。更新日期：2026-10-28。

Book Skill 让 Codex 按固定流程在 Anna’s Archive 查找电子书，比较版本与格式，整理下载链接，并在你明确要求下载后，把选中的文件保存到运行环境中并校验。

它是一组 Agent 工作流指令，安装包不包含模型、浏览器、代理、图书文件或网站账号。只把这份教程粘贴进普通聊天窗口，不会自动获得浏览器控制和本地下载能力。

## 先了解使用方式

| 你的要求 | Skill 的行为 |
| --- | --- |
| 搜一下《小王子》，先不下载 | 搜索、选版本、解析页面上真实的最终下载链接，列出四列表格；不点击最终下载按钮 |
| 找《小王子》的中文 EPUB | 只保留符合语言和格式要求的结果，不用 PDF 或英文原著代替 |
| 对比几个译本 | 使用同一表格，突出译者、出版社、年份等差异 |
| 只看书目记录，不解析下载链接 | 进入 record-only 模式，只提供记录页 |
| 下载上面的 A1 | 复用已找到的入口，必要时刷新过期链接，串行下载并校验 |
| 下载这三本并打包 | 逐本下载，全部验证完成后统一命名、打包并检查压缩包 |

未指定格式时，默认优先列出一本书最合适的 EPUB 与 MOBI/AZW，每本最多两行；缺少这些格式时才选其他可用格式。可以明确要求 PDF、更多版本或某种语言。查到链接只表示提取成功，文件能否完整传输要等实际下载后验证。

## 必要环境

### 能运行 Skill 的客户端

需要一个支持加载 `SKILL.md`、调用浏览器工具、读取工具结果的 Agent 客户端。本次完整测试使用 macOS 上的 Codex 和 Google Chrome。

Codex 的桌面、CLI、IDE 环境能加载本地技能；不同客户端的可用工具、权限与运行位置可能不同。工具运行在云端时，文件通常保存到云端工作区，不会自动落到你电脑的“下载”文件夹。官方技能说明见 [Build skills](https://developers.openai.com/codex/skills)。

| 环境项 | 是否必需 | 用途与验收方式 |
| --- | --- | --- |
| 可用的模型登录或 API 配置 | 必需 | 普通请求能收到真实回答；模型名称出现在列表中不等于可调用 |
| 浏览器自动化工具 | 必需 | 能打开网页、读取 DOM/iframe、点击与填写表单，并查看截图 |
| 图片理解能力 | 遇到视觉验证码时需要 | 截图必须真正送到支持视觉输入的模型；仅有网页文字不足以识别图片内容 |
| 下载事件与文件访问 | 实际下载时必需 | 能把浏览器下载事件对应到保存的文件，并读取字节进行校验 |
| 可写目录与足够磁盘空间 | 实际下载时必需 | 能创建文件、保存完整电子书；打包还需要额外空间 |
| Node.js、npm/npx、Playwright | 仅采用该浏览器方案时 | 已有原生浏览器工具时不必重复安装；版本由所用工具的文档确定 |
| Python 3 或等效文件校验工具 | 校验时按环境提供 | 用于摘要、ZIP/EPUB 结构检查；Skill 本身不包含固定 Python 服务 |
| `pdfinfo` 或适合该格式的校验器 | 缺少可信摘要时按需 | PDF 可用 `pdfinfo` 检查可解析性；其他格式也需有对应验证手段 |
| 本地 GPU | 云端模型方案不需要 | 本机主要运行客户端、浏览器和文件处理，不要求本地部署大模型 |

Windows、Linux 或远程服务器要分别准备可用浏览器、目录权限和下载能力；本次未逐个平台验收。无界面服务器不应直接套用本机 Chrome 的安装路径。浏览器工具缺失时先解决工具配置，反复切换 GPT 模型不会补出工具。

## GPT 怎么选

### 先检查能力，再选择型号

完整流程需要模型理解中文书名与版本、遵循表格规范、连续调用工具并根据页面反馈修正操作。视觉验证码还要求模型能够接收并理解当前截图。只支持纯文本、只返回聊天答案或无法调用工具的接入方式不满足完整流程。

下表是结合本 Skill 工作特点给出的起点，并非四款模型的同条件成功率测试。官方对模型定位与推理强度的说明见 [Models](https://developers.openai.com/codex/models)。

| 模型 | 建议用途 | 使用条件 |
| --- | --- | --- |
| `gpt-6.1-sol` | 日常搜书、版本选择、连续浏览与下载流程的默认起点 | 当前账号和上游实际支持；从客户端默认推理强度开始 |
| `gpt-6.1-terra` | 需要较多页面截图理解、表单操作时可试用 | 接入链路必须保留视觉与工具能力；CLI 使用它需 0.159.0 或更高版本 |
| `gpt-6-astra` | 版本辨认复杂、长流程反复出错时的可选升级 | 通常无需为一次简单搜书直接选择最高推理强度 |
| `gpt-6-luna` | 目标明确、流程重复的搜索或元数据整理 | 遇到复杂页面先检验实际表现，不承诺与更强模型相同的完成率 |

模型列表、价格、额度和可用推理档位会变化；以当前客户端、所用服务商以及真实请求结果为准。提高推理强度可能增加等待与消耗，也不能修复浏览器断连、网络不通或网站限流。多本书的实际文件传输仍然串行。

### 使用 Senmora / New API

先按 [CC Switch 导入密钥并使用 Codex](https://doc.senmora.top:38483/docs/cc-switch-codex/) 完成客户端配置。此站点的 OpenAI 兼容 API Base URL 为：

```text
https://www.senmora.top:3443/v1
```

这个地址用于模型请求。Anna 网页和合作下载站由浏览器从其所在环境访问，New API 不会自动代理这些网页流量。CC Switch 切换模型供应商，也不等于给 Chrome 配置网络代理。

当前 Codex 自定义供应商要求兼容 Responses API；仅支持 Chat Completions 的接口不足以接入当前流程。还要保留流式响应、工具调用与工具结果、会话续接，以及需要时的图片输入。不要只看到 `/v1/models` 中有模型就认定完整链路可用。参见 [自定义供应商与网关兼容性](https://developers.openai.com/codex/models#other-models)。

建议按顺序验收：普通短回答成功 → 工具调用有真实结果 → 当前截图能被读懂 → 浏览器能完成一次真实搜书 → 明确要求下载后文件校验通过。遇到 API 401/403，检查密钥与权限；余额、分组、上游模型限制按站点当前设置排查，不要公开粘贴密钥。

使用 OpenAI 官方登录时，可用 ChatGPT 登录或 API Key，两者的额度和计费来源不同；使用 Senmora 密钥时按 Senmora 的账户与计费规则处理。这份 Skill 不附带任何额度或订阅。[官方认证说明](https://developers.openai.com/codex/auth)

## 网络需要哪些条件

| 链路 | 必须能访问什么 | 常见表现 |
| --- | --- | --- |
| 模型链路 | 你配置的模型 API 或官方登录服务 | Codex 无法回答、认证失败、流式请求中断 |
| 安装链路 | GitHub；采用 npm 浏览器工具时还包括其软件包与浏览器下载来源 | Skill 或运行依赖安装失败 |
| 搜索链路 | 当前可用的 Anna 域名及验证页面依赖 | 网页打不开、证书/DNS 错误、停留在验证页面 |
| 文件链路 | 页面实际给出的合作下载域名 | 搜索正常，但下载排队、限流、断流或失败 |

是否需要代理取决于你所在网络及目标站点的实际可达性，没有“一定直连”或“一定需要某个地区”的前提。模型、终端和 Chrome 可能使用不同出口，要检查真正执行该步骤的进程。若使用代理，应确认它覆盖需要的浏览器流量，并尽量在一次验证、排队和下载期间保持会话与出口稳定。

浏览器必须能正常解析域名、建立 HTTPS 连接并校验证书。网站能返回首页，也不等于 iframe 验证资源或下载域名全部可达。不要用关闭 TLS 校验或降低 Chrome 安全保护来掩盖问题。

Skill 内置若干 Anna 候选域名，并优先复用已成功的入口。只有真正的主机访问失败才会触发有限的新域名发现：先查指定 Reddit 社区，再按需查 Wikipedia 与 SLUM，共用最多两个新域名尝试名额。出现验证码本身不表示域名失效，不会为躲避未完成的验证反复换站。

## 安装完整技能包

源码在 [StealHD/gitSkills](https://github.com/StealHD/gitSkills/tree/main/skills/book-skill)，本教程对应 [v0.2.5 发布页](https://github.com/StealHD/gitSkills/releases/tag/book-skill/v0.2.5)。升级或复现时可从发布页获取固定版本的 ZIP 或 tar.gz。

### 方式一：让 skill-installer 安装

在支持该内置技能的 Codex 会话中输入：

```text
使用 $skill-installer 安装 https://github.com/StealHD/gitSkills/tree/main/skills/book-skill
```

安装后确认 `book-skill` 出现在技能列表中。若新技能或更新未出现，重启客户端再检查。

### 方式二：手动安装

解压发布包，将整个 `book-skill` 文件夹放到客户端扫描的技能目录。当前官方文档列出的用户目录为 `~/.agents/skills`，项目目录为 `.agents/skills`。本次测试环境已有 `~/.codex/skills/book-skill`，由该客户端加载；这属于实际环境路径，不应当作所有客户端版本通用的唯一路径。按客户端的技能列表确认最终加载位置。[官方目录规则](https://developers.openai.com/codex/skills#where-to-save-skills)

应保留以下完整结构：

```text
book-skill/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── browser-stability.md
    ├── download-workflow.md
    └── output-formats.md
```

`SKILL.md` 负责搜索和选择；`browser-stability.md` 负责浏览器、验证和恢复；`download-workflow.md` 负责实际传输及校验；`output-formats.md` 规定输出格式。只复制主文件会遗漏关键规则。这份用户教程是阅读材料，不代替技能包。

升级前保留旧版本备份，替换同一个已加载目录中的完整技能包。不要在多个扫描目录留下同名新旧技能，避免同时出现、选错版本。安装不需要把 API Key、浏览器 Cookie 或私人下载链接写进技能文件。

## 第一次使用

先运行一次不下载的搜索：

```text
使用 book-skill 搜一下《小王子》，按原来的表格列出不同格式让我选，先不下载。
```

若要避免解析最终链接时的排队，可以明确说：

```text
只查《小王子》的中文书目记录，列出版本和格式，不解析下载链接，也不下载。
```

找到结果后继续：

```text
下载上面的 A1，保存到我的下载目录。
```

也可以一次说明需求：

```text
查找《动物农场》和《1984》的中文 EPUB，先列结果，不下载。
```

提供译者、出版社、年份或 ISBN 能减少同名与版本歧义。需要实际保存时明确说“下载”；只要求“搜一下”会准备最终链接，但不会点击最终文件下载动作。“先不下载”仍可能需要通过验证和等待入口就绪，这与文件传输是两个阶段。

一本书和多本书都使用四列；每种格式独占一行。下面是排版示意，不是新的搜索结果，操作文字没有附带可用下载链接：

已找到 1 本。

| 选择 | 书籍／版本 | 文件 | 操作 |
| --- | --- | --- | --- |
| A1 推荐 | 《小王子》译本甲 · 译者／出版社／年份以记录为准 | 中文 · EPUB · 以记录为准 | 下载 · 记录 · 刷新入口 |
| A2 | 《小王子》译本乙 · 译者／出版社／年份以记录为准 | 中文 · MOBI · 以记录为准 | 下载 · 记录 · 刷新入口 |

正式搜索中，“下载”指向页面上实际出现的最终 HTTPS 下载动作；“记录”指向书目页；“刷新入口”指向成功解析过的下载入口。三者不能互相冒充。完整结果保留三个短标签，不显示长串签名参数。

书籍数量按作品统计，不按格式行统计。未知的译者、出版年份等直接省略，不编造。未找到指定格式时如实标记；链接解析失败时保留已有记录与成功结果，不制造一个“下载”链接。默认表格之后不再追加“回复 A1 即可”等选择提示。

签名链接可能过期，不适合长期收藏；回到刷新入口或让 Skill 刷新同一入口即可。只看书目模式保留记录链接，不要求补齐另外两项。

## 遇到人机验证时如何处理

新版把可操作的人机验证作为浏览步骤的一部分。在当前平台与工具规则允许的情况下，先检查页面并完成正常界面操作，而不是看到“人机验证”就立即让用户代点。

1. 检查验证区域；顶层页面只有 iframe 时继续读取该 frame，必要时查看局部截图。
2. 点击可见的“我不是机器人”等控件，观察是否出现图片或文本验证码。
3. 对支持的视觉题，读取当前图片和说明；文本验证码按看见的内容填写，保留大小写。字符不清晰先放大查看，不循环猜字符。
4. 提交后观察明确反馈。图片改变就重新识别，按钮消失本身不等于通过。
5. 看到目标搜索结果或下载动作后，立即沿原会话继续，不重复成功步骤。

单次验证处理最多 120 秒；下载入口原本的 120 秒期限仍是外层限制，重试不会重新计时。图片始终看不清、连续返回同一验证、明确拒绝、需要本人登录或时间用完时，保留当前标签页，说明具体需要你操作哪一步。不会通过伪造验证状态绕过网站或工具限制。

有图片理解能力不代表能识别所有验证码。外部打码服务不是必要依赖；宿主能力与规则不支持时仍需人工协助。普通页面等待、验证码操作、浏览器重连、文件传输重试分别计数，不能混为无限重试。

## 实际下载与文件校验

你确认下载后，Skill 会复用已有结果，逐本串行处理。点击一次最终动作后绑定浏览器下载记录，确认它对应的实际文件；点击结果不明确时先查文件和下载状态，不立即再点一次。

完成至少需要：浏览器报告完成、实际文件非空、约 15 秒间隔的两次采样大小稳定、真实文件类型正确，以及所有可获得的可信 MD5 和精确字节数一致。网页上四舍五入的“3.1 MB”不能充当精确大小证据，HTML 错误页也不能因为后缀是 `.epub` 就当成书。

缺少可信摘要时执行格式结构检查：EPUB 检查 ZIP CRC、mimetype、container.xml 与其引用的包文档；PDF 使用可用的 `pdfinfo` 检查解析和页数等元数据；其他格式使用对应校验器。缺少工具或证据时标记“完整性未确认”，不假称校验通过。

首次明确传输失败后冷却 60 秒，全任务只允许一次传输恢复：优先安全的继续／恢复按钮，否则使用未尝试的同入口 HTTPS 兄弟动作，再否则刷新成功入口启动一次新传输；三种方式择一。恢复后再次明确失败就停止整个批次。持续 180 秒无字节增长时检查一次并按实际状态暂停自动监控。校验失败不自动重下。

所有选中文件验证通过后再统一命名为规范书名；同名不同内容避免覆盖。要求打包时检查压缩包成员与完整性，不能悄悄把缺书的子集交付为“全套”。停止自动监控不代表浏览器中的传输一定已经取消。

### 下载后的输出

单个文件用一句真实状态说明，并附实际文件链接，例如：

```text
《小王子》已下载并校验通过：[小王子.epub]（实际文件路径）。
```

多本下载使用三列，以下仅示意部分完成时的格式：

| 书籍 | 状态 | 文件 |
| --- | --- | --- |
| 《书 A》 | 已保存 | 实际已验证文件的链接 |
| 《书 B》 | 下载限流，已停止自动尝试 | |
| 《书 C》 | 未开始 | |

正式结果不会把未验证文件或 `.crdownload` 临时文件链接成已完成的书。部分失败时保留已完成项，不用一条笼统报错覆盖全部结果。详细导航日志只在明确要求调试时提供。

## 常见问题排查

| 问题 | 优先检查 |
| --- | --- |
| 安装后找不到 Skill | 目录是否被当前客户端扫描；文件名是否为 SKILL.md；是否保留完整结构；重启后是否出现 |
| API 能回答，但不会打开网页 | 当前会话是否真的有浏览器工具与相应权限；模型回答中声称“打开了”不是执行证据 |
| 模型能看图片，仍无法识别验证码 | 截图是否真正传入、是否足够清晰、图片是否已刷新；不要复用旧答案或硬猜 |
| 只看到 iframe 就停住 | 使用工具支持的 frame 定位或局部截图；顶层 DOM 不等于验证区域全貌 |
| Browser is not available | 查实际可用的浏览器接口；一个 provider 不可用不等于 Chrome 未安装或网站故障 |
| Playwright 安装或缓存 EACCES | 核对所用运行时与缓存目录权限；采用已提供的受支持运行时，避免用 sudo 安装制造更多属主混乱 |
| 能搜到，但下载入口长时间等待 | 看页面的倒计时、验证或限流信息；入口期限内观察，符合条件时只试一次备用路线 |
| 429 / 同 IP 并发限制 | 按下载限流处理，维持串行和冷却；不能据此说整个 Anna 服务宕机 |
| 下载链接过期 | 复用刷新入口取得当前动作，不拼接或猜测签名 URL |
| 显示已下载，文件打不开 | 检查是否 HTML 错误页、部分文件、摘要/字节数或结构不符，暂停后续队列 |
| 搜索正常但没有指定格式 | 标记“未找到指定格式”；需要改格式由用户明确提出，不静默换成别的语言或作品 |
| 输出变成了调试步骤清单 | 确认加载的是完整最新版，并让 Agent 读取 references/output-formats.md 后按固定表格重排 |

Anna 访问失败不会自动授权改用其他书源。需要其他来源时，明确提出来源或允许范围。
